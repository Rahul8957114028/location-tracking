2. Critical Viva Questions & Model Answers
Q1: Can someone's exact live location be tracked just with their phone number?

Answer: No. In real-world telecommunications, an external civilian cannot obtain real-time GPS coordinates of another device merely by querying a phone number. Telecom operators maintain subscriber location in HLR/VLR registers, accessible only to law enforcement under lawful intercept warrants (e.g., Section 5(2) of Indian Telegraph Act). Public APIs return Telecom Circle (State) and Carrier details. Real-time GPS tracking requires on-device GPS authorization via the HTML5 Geolocation API.

Q2: How does the HTML5 Geolocation API obtain the device's location?

Answer: The Geolocation API uses a hybrid positioning system:
1. GPS (Global Positioning System): Direct satellite signals (~5-10m accuracy, outdoors).
2. Wi-Fi BSSID Positioning: Compares visible Wi-Fi access points against geolocated MAC databases.
3. Cell Tower Triangulation: Computes timing advance and signal strength from nearby GSM/LTE cell towers.
4. IP Geolocation: Broad ISP city-level estimation (fallback).

Q3: What is the difference between getCurrentPosition() and watchPosition()?

Answer: getCurrentPosition() fetches a one-time snapshot of the current location and immediately terminates. watchPosition() establishes an ongoing listener stream that automatically invokes the callback whenever the device's sensor detects physical movement, returning updated coordinates, speed, and heading. It returns a watchId used to cancel tracking via clearWatch(watchId).

Q4: What is Geocoding and how is it used in the Pincode Tracker?

Answer: Geocoding is the computational process of transforming descriptive location text (such as a 6-digit postal PIN code and district name) into geographic coordinates (Latitude and Longitude). Our application first queries the India Post API to obtain post offices and district metadata, then submits this structured query to the OpenStreetMap Nominatim Geocoding API to receive exact boundary coordinates to render on the Leaflet map.

Q5: What are the security and privacy measures implemented in this project?

Answer:
1. Explicit User Consent: Geolocation requests trigger standard browser permission prompts.
2. HTTPS Requirement: Browsers restrict Geolocation APIs to secure HTTPS contexts or localhost.
3. Client-side API Key Masking: Sensitive API keys can be proxied through the optional Node.js / Express backend to avoid exposing credentials in client scripts.
4. No Unauthorized Data Storage: No personal coordinates are stored in remote tracking databases without user action.

Q6: What is GeoJSON and why is it useful in this project?

Answer: GeoJSON is an open, JSON-based geospatial data interchange format defined in RFC 7946. It represents geographical features (Points, LineStrings, Polygons) alongside non-spatial attributes. Our project supports exporting the recorded live device tracking breadcrumb route as a standard GeoJSON LineString file, compatible with GIS software such as QGIS and Google Earth.
